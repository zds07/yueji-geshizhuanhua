# 出稿前自检规则（源自用户改稿回读）

> 这份规则不是"怎么转换"，是**脚本生成完、交付给用户之前怎么自查**。
> 来源：用户在我生成的制作版上亲手改过一轮，回头比对他的删除动作反推出来的。
> **写脚本时犯的错几乎全在这五条里**，出稿前逐条过一遍能省掉一整轮返工。

---

## 零、先说一个观察：用户只改前几镜

回读时发现用户**只动了前 4 镜**，后半段一个字没改。

这不是他懒，是脚本的规律：**前 3-4 镜是全片的样板，读者在那里形成对整份稿子的语气判断。**
样板不对，后面他根本读不下去，或者带着"这稿不对"的预设在看。

**做法**：长脚本（10 镜以上）不要一次铺满再交付。
先出前 3-4 镜让用户确认语气，对了再铺全片。省掉的是整篇返工。

---

## 一、台词必须匹配"人此刻在做什么"

这是"文字怪怪的"最主要的来源。**人不会在做 A 动作的时候说 B 台词。**

| 画面里人在做什么 | 台词该说什么 | 不该说什么 |
|---|---|---|
| 站着看 / 走着指 / 指点某物 | 可以介绍、讲解、报价、讲来历 | 长段感慨 |
| **落座开吃 / 坐下谈事** | 招呼、点评这道菜、即兴感慨 | **念门店介绍、念品牌来历、念权益** |
| 交易 / 对账 / 收单据 | 短句确认、埋下一站钩子 | 大段总结陈词 |
| 转场路上 | 一问一答推进 | 独白式介绍 |

**实例**（已被用户改掉的一句）：
落座吃饭那一镜，介绍角色原句写的是「他们门口那桶茶，一年到头谁都能倒」——
这是**门店介绍**，念导购词。用户改成「今天这可都是招牌菜」——变成**招呼客人**。

**自检句**：这一镜里人是站着还是坐着？**坐着就别让他介绍。**

**连带检查**：同类镜要一视同仁。
用户改了第一站的吃饭镜，第三站、第三站的吃饭镜如果还是介绍句式，是他没往下看，不是他认可。回流量较大的稿子要主动把同型镜一起改了再交付。

---

## 二、道具列只写"没人张罗就不会出现在画面里"的东西

道具 = **制片要提前准备 / 协调的清单**，不是"画面里会出现什么"。

用户删掉的：
- `办公桌、公文包` —— 办公室本来就有
- `一整桌具体菜名、碗勺` —— 商家上门就上，不用你准备

用户保留的：
- `美食地图手卡` —— 要专门设计制作
- `门口的免费茶桶、茶杯、老式杆秤` —— 要从店里搬出来摆好
- `当日到货海鲜、明档水箱` —— 要跟后厨打招呼才拍得到

**自检句**：这东西我不专门张罗，它会出现在画面里吗？
**会 → 不写。不会 → 写。**

**副产物**：菜名、酒水这类"商家提供物"不该进道具列，但确实要出现在画面里 ——
那属于 `画面内容` 或 `镜头设计`（要拍到什么），不属于你要准备什么。

---

## 三、备注只写"开机前要当面交代的一件事"

备注是给**统筹 / 制片**看的待办，不是给甲方看的设计说明，也不是给摄影师的方法论。

用户删掉的：
- `客户身份只在办公室段点明一次，现场三站不再强调` —— **这是设计理由，删**
- `需商户配合按顺序上菜、允许拍摄进食过程；建议固定机位拍完一整段后期挑`
  → 压成 `需商户配合上菜` —— 后半是**拍摄方法论**，不该进备注

用户保留的：
- `美食地图手卡需提前制作` —— 明确的待办
- `开场第一句定钩子，语气要冲；核心关键词咬清楚` —— **表演提示，可以留**

**判定三分法**：

| 内容类型 | 留否 | 例子 |
|---|---|---|
| 开机前要落实 / 要协调 / 要交代的事 | ✅ 留 | 手卡需提前制作、需后厨配合、语气要冲 |
| 拍摄方法论（怎么拍、几个机位） | ❌ 删 | 建议固定机位拍完一段后期挑 |
| 设计理由（为什么这么写） | ❌ 删 | 身份只在某段点明一次 |

**长度上限**：一条备注一件事，超过两句就该拆或砍。

## 四、一条备注里混了三类东西 → 用户会整条删掉

用户把某镜备注**整条清空**，里面同时塞了这三种：

1. `【待提供】本镜权益内容，句尾留 2s 空档` —— 待确认占位
2. `福茶桶与老秤需商户允许拍摄` —— 拍摄协调
3. `街口人流傍晚拍，行人正脸需避让` —— 合规/避让要求

他不是逐项挑着删，是**整条删**。说明"分类混杂的备注"在他眼里等于噪音。

**做法**：

- **待确认项（权益 / 客户未提供的内容）一律移出备注**，单独做一张「待确认清单」交付。
  备注里塞 `【待提供】` 是给摄制组看的无用信息，还会被当成噪音删掉。
- 拍摄协调和合规要求如果是**必须遵守**的，留一句最短的；可选项一律不写。
- 一条备注 = 一个责任人要做的一件事。

## 五、改稿回流后必须回读校验（结构层面）

用户在 Excel 里插入一行后，脚本结构坏了但表面看不出来：

- 后面所有**镜号整体偏移 +1**
- **幕标题里的镜号范围没跟着更新**（第四幕还写着「镜 7-8」，实际已是 8-9）
- 信息头「镜号数」与真实镜数不符

**任何插入 / 删除 / 重排之后，回读必须校验三项**：

```python
# 1. 幕标题里的「镜 X-Y」是否与实际包含的镜号一致
# 2. 信息头「镜号数」== 实际镜数
# 3. 有没有中间空行（有镜号但其他列全空）
```

**尤其注意**：用户可能在 Excel 里手工插入过行。
脚本介入前**先 dump 一遍全表的「镜号 + 拍摄地点」**，确认没有错位和空行，
再决定在哪插 —— 否则会把内容写到错位的行里。

## 自检清单（出稿前过一遍）

```
□ 每一镜：人是站着还是坐着？坐着的台词是不是在念介绍？
□ 同类型镜（每个吃饭镜 / 每个转场）台词句式是否一致处理？
□ 道具列：有没有"场景自带"或"商家提供"的东西混进来？
□ 备注：有没有一句话是在解释"为什么这么设计"？
□ 备注：有没有超过一句话？
□ 备注：有没有混进【待提供】占位？（有 → 移到单独的待确认清单）
□ 幕标题镜号范围 == 实际镜号？
□ 信息头镜号数 == 实际镜数？
□ 有没有中间空行？
□ 前 3-4 镜是否已让用户确认过语气？
```
